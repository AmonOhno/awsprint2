# 運用規約(RULES)

このリポジトリの開発・運用ルール。変更があればこのドキュメントを更新してから作業する。

## 1. ブランチ運用

- 現フェーズでは **main ブランチへ直接コミットしてよい**(2026-07-19 ユーザー指示)。
- フェーズ移行(複数人開発・公開運用の開始)時にブランチ戦略を再検討し、本節を更新する。
- コミットメッセージは「何を・なぜ」を1行目に日本語で簡潔に書く。

## 2. ゼロコスト原則

- 有料の外部サービス・API・サーバーは使用しない。
- Web版は静的ファイルのみ(ブラウザで直接開く、または GitHub Pages 無料枠)。
- iOS版は App Playground(`.swiftpm`)形式とし、有料の Apple Developer Program に依存しない。
- 学習進捗などのユーザーデータは端末内(localStorage / UserDefaults)にのみ保存し、外部送信しない。

## 3. 問題データの管理(単一ソース)

- 問題データの単一ソースは `data/questions.json`。**ここ以外を直接編集しない。**
- `web/data/questions.js` と `ios/AWSStudy.swiftpm/Resources/questions.json` は自動生成物。
- データを変更したら必ず `scripts/sync-questions.sh` を実行し、生成物も同じコミットに含める。
- 問題追加時の品質基準:
  - 4択・正解1つ、`answer` は choices のインデックス(現状はすべて 0 で、表示時にシャッフルされる)。
  - 解説は「なぜ正解か」+「他の選択肢との違い / 覚え方」を2〜4文で書く。
  - `category` は既存6カテゴリのいずれかに揃える(新カテゴリ追加時は Web/iOS の表示確認を行う)。

## 4. アーキテクチャ図レビュールーチン(2026-07-19 限定)

- **内容**: `docs/architecture.md` を実際のコード構成と突き合わせてレビューし、乖離があれば図と説明を修正してコミットする。
- **頻度**: 2026-07-19 の間のみ、1時間おき(毎時7分。負荷分散のため 0分を避ける)。
- **実施方法**: Claude Code のセッション内スケジュールジョブとして登録済み(cron `7 * 19 7 *`、ジョブID `f1617065`)。
  - このジョブは**リポジトリにリモートがないためローカル実行**であり、登録した Claude Code セッションが開いている間のみ動作する。セッションを閉じるとルーチンは停止する(再開したい場合は同じ cron 式で再登録)。
- **レビュー観点**:
  1. 図に描かれたファイル・ディレクトリが実在するか
  2. データフロー(単一ソース → 同期 → 各アプリ)が実装と一致しているか
  3. 生成物を直接編集した痕跡がないか(あれば同期スクリプトで復元)
  4. 修正した場合は `docs/architecture.md` の「最終レビュー」日時を更新
- **終了処理**: 2026-07-19 の最終レビュー後にジョブを削除する(セッション終了でも自動的に消える)。削除・終了したら本節に完了日を追記する。

## 5. 変更時の確認事項

- Web: `web/index.html` をブラウザで開き、クイズ1周・弱点復習・フラッシュカードの動作を確認。
- iOS: Xcode で `ios/AWSStudy.swiftpm` を開きシミュレータでビルド確認(Mac 上で可能な場合)。
- 進捗データのスキーマ(`{attempts, correct, wrongStreak}`)を変更する場合は、Web と iOS の両方を同時に変更し、ストレージキーのバージョン(`awsstudy.progress.v1`)を上げる。
